## STL の 3 本柱

STL は大きく 3 つの部品からできています。この 3 つは「分業」しており、
互いに直接は依存しません。これが STL の最大の発明です。

```
┌───────────────┐     ┌───────────────┐     ┌───────────────────┐
│  コンテナ      │ ──▶ │  イテレータ    │ ◀── │  アルゴリズム      │
│ (データを持つ) │     │ (橋渡し)       │     │ (処理を行う)       │
│ vector,list.. │     │ begin()/end() │     │ find, sort, ...   │
└───────────────┘     └───────────────┘     └───────────────────┘
```

### 1. コンテナ (Container)

データ（要素）を入れておく「入れ物」です。代表例：

| コンテナ | 特徴 | 得意なこと |
|----------|------|-----------|
| `std::vector` | 連続したメモリの動的配列 | 末尾追加・添字アクセス(`v[i]`)が速い |
| `std::list`   | 双方向リンクリスト | 途中の挿入・削除が速い（添字アクセス不可） |
| `std::deque`  | 両端キュー | 先頭・末尾どちらの追加も速い |
| `std::map`    | キーと値のペア（連想配列） | キーで探す |
| `std::stack`  | LIFO のアダプタ（後述） | てっぺんだけ触る |

### 2. イテレータ (Iterator)

コンテナの「要素を指す矢印（ポインタの一般化）」です。
コンテナの種類が違っても、イテレータの操作の仕方は共通です（後述）。

### 3. アルゴリズム (Algorithm)

`<algorithm>` などに用意された「処理のテンプレート関数」です。
`std::find`（探す）, `std::sort`（並べ替える）, `std::min_element`（最小を探す）など。
**アルゴリズムはコンテナを直接知らず、イテレータ越しに仕事をします。**

## イテレータとは何か

イテレータは「**コンテナの要素を 1 つ指す矢印**」です。
ポインタを一般化したものだと考えると分かりやすいです。
どんなコンテナのイテレータでも、最低限つぎの操作ができます。

```cpp
*it      // それが指している要素の中身を読む（または書く）
++it     // 次の要素へ進める
it == x  // 別のイテレータと同じ位置か比べる
it != x  // 別のイテレータと違う位置か比べる
```

そして、すべてのコンテナは

```cpp
container.begin()  // 先頭要素を指すイテレータ
container.end()    // 「末尾の 1 つ後ろ」を指す番兵（イテレータ）
```

を提供します。`end()` は**最後の要素ではなく、その「次」**を指す
ことに注意してください。だから走査は次のように書きます。

```cpp
for (std::vector<int>::iterator it = v.begin(); it != v.end(); ++it)
    std::cout << *it << std::endl;  // *it で中身を取り出す
```

`begin()` から `end()` まで `++` で進み、`end()` に達したら止まる――
この `[begin, end)` という「半開区間」が STL 全体の共通ルールです。

### iterator と const_iterator

- `iterator`        … 指す先を**書き換えられる**矢印（`*it = 5;` が可能）
- `const_iterator`  … 指す先を**読むだけ**の矢印（`const` なコンテナで使う）

## アルゴリズムがイテレータで動く仕組み

STL の核心は「**アルゴリズムはコンテナの種類を知らない**」ことです。
たとえば `std::find` の中身を擬似コードで書くと：

```cpp
template <typename It, typename T>
It find(It first, It last, const T& value)
{
    while (first != last)   // 番兵 last に達するまで
    {
        if (*first == value)  // 中身が一致したら
            return first;     // その位置を返す
        ++first;              // 次へ
    }
    return last;              // 見つからなければ last
}
```

ここで使っているのは `*first` / `++first` / `first != last` の
**3 つの操作だけ**です。これは vector でも list でも deque でも
（さらには生ポインタでも）共通して使えます。だから **1 つの `std::find`
だけで、あらゆるコンテナに対して「探す」ことができる**のです。

これが「コンテナ N 種類 × アルゴリズム M 種類」を `N×M` 個の関数で
書かずに済む、STL の設計の美しさです。橋渡しをしているのがイテレータです。

このモジュールでは ex00 がまさにこの考え方の練習で、`std::find` を
テンプレート関数 `easyfind` から呼び、vector / list / deque すべてに
1 つのコードで対応します。

## コンテナアダプタ（stack）とは

`std::stack` は「**コンテナアダプタ**」と呼ばれる特殊なコンテナです。
自分でデータを持たず、**内部に別のコンテナ（既定は `std::deque`）を
抱えて、その一部の操作だけを別のインターフェースとして見せます**。

`std::stack` が見せるのは「LIFO（後入れ先出し）」の操作だけ：

```cpp
std::stack<int> s;
s.push(1);            // 積む
s.push(2);
std::cout << s.top(); // てっぺんを見る → 2
s.pop();              // てっぺんを降ろす
```

`std::stack` は `begin()` / `end()` / `iterator` を**一切提供しません**。
だから for ループで全要素をなめることが**できません**（反復不可）。
ex02 ではこれを継承して、内部コンテナのイテレータを外に露出させた
`MutantStack` を作り、反復できるようにします。

## 全体のビルド方法

各演習は独立した `Makefile` を持ちます。各フォルダで `make` してください。

```bash
# ex00
cd ex00 && make && ./easyfind

# ex01
cd ex01 && make && ./span

# ex02
cd ex02 && make && ./mutantstack
```

すべて次のフラグでコンパイルされ、警告・エラーはゼロです。

```
c++ -Wall -Wextra -Werror -std=c++98 ...
```

各 `Makefile` のルール：`NAME` / `all` / `clean` / `fclean` / `re`。
（不要な再リンクは起きません。メモリリークもありません。）

- `std::sort`（ex01：最短スパンのための並べ替え）

- `std::min_element` / `std::max_element`（ex01：最小/最大の検索）

これらを「手書きループの代わり」に積極的に使っている点が、このモジュールの
評価ポイントです。
